# 08 — Importers

Three ramps into a project, ordered by value per unit of work.

## Problem

OpenAPI import works today, server-side, and requires an OpenAPI document. Most
people wanting a mock have something else: a browser session, a Postman
collection, or a `curl` command a colleague pasted into chat.
`CreateProjectModal.tsx:11-12` shows Postman and Example as permanently
"Coming soon" cards.

## 8.1 HAR — highest value, do first

Every browser's devtools exports HAR, so "mock what my app just did" becomes a
drag-and-drop. It is also the only importer that carries **real response bodies**,
which is what makes a mock useful.

- Parse `log.entries[]`. Per entry: method, URL, status, response body, content
  type, request body.
- **Filter before importing.** A HAR from a real page is mostly noise: offer
  include/exclude by host, by content type (default: JSON and text only), and by
  status class. Show a preview table with per-row checkboxes and a count.
- **Group by path**, offering `:param` for segments that vary across entries and
  look like identifiers (uuid, all-digits, hex over 16 chars). Getting this right
  is the difference between 4 rules and 400.
- Repeated identical method+path collapse into one rule; differing bodies become
  numbered variants the author picks between, or a sequence via plan 10.
- **Redaction on import**, reusing plan 04's rules. A HAR is dense with cookies
  and bearer tokens, and it arrives as a file the user may not have read.

Cap: 5 MB / 500 entries per import, with a clear error past it.

## 8.2 cURL paste — cheapest, do second

A textarea. Paste `curl -X POST https://... -H '...' -d '...'`, get a rule.

Parse a deliberately small flag set: `-X/--request`, `-H/--header`,
`-d/--data/--data-raw/--data-binary`, `-u/--user`, `--url`, plus the bare URL.
Anything unrecognised is reported, not silently dropped — a mock built from a
half-understood command is worse than a rejection.

The path becomes the rule path, the body becomes `match` conditions on its
top-level fields (author-editable before save), and the response is a stub the
author fills in. Round-trips with the existing `src/viewer/curl.ts` generator, and
its test corpus is that generator's output.

## 8.3 Postman collection — most requested, do third

Collection v2.1 JSON. Per request: method, URL (Postman `{{var}}` placeholders
mapped to `:param` where they sit in a path segment), headers, body.

- **Saved example responses** in the collection become response bodies. Without
  them the import yields empty stubs, so surface that count up front: "38 requests,
  6 with saved examples".
- Collection variables map to plan 17 environment variables.
- Folders become rule-file groupings on export.
- Pre-request and test scripts are **ignored, with a visible count** —
  they are JavaScript and are out of scope permanently (design doc §4.8).

## Shared design

One pipeline, three parsers:

```
file/paste → parse → RuleDraft[] → preview + edit + select → validate → save
```

`RuleDraft` is `ruleSchema`'s shape plus provenance (`source: "har" | "curl" |
"postman"`, `sourceRef`). **Nothing imports without a preview step** — a silent
bulk write into live config is how a mock server becomes untrustworthy.

Collision handling: an existing rule with the same method+path is shown side by
side with the incoming one; choose skip, replace, or add-as-variant.

## Tests

- A HAR from a real session imports the expected rule count after filtering.
- Path parameterisation: `/users/8f3a.../orders` and `/users/2b1c.../orders`
  collapse to `/users/:id/orders`.
- HAR cookies and bearer tokens are redacted on import.
- A `curl` command generated by `src/viewer/curl.ts` re-imports to an equivalent
  rule (round-trip property test).
- An unrecognised curl flag is reported, not dropped.
- A Postman collection with saved examples produces bodies; one without produces
  stubs and an accurate count.
- Import over an existing rule respects the chosen collision strategy.

## Risks

| risk | mitigation |
|---|---|
| A HAR import creates hundreds of junk rules | Filter defaults are aggressive, preview is mandatory, path grouping is shown before save. |
| Secrets imported from a HAR | Redaction on the import path, same rules as plan 04. |
| Postman format drift | Support v2.1 only; reject others by name with a link, rather than half-parsing. |

## Rollback

Hide the import tabs. Imported rules are ordinary rules and are unaffected.

## Done when

A HAR from a browser session becomes a working project in under two minutes, a
pasted `curl` becomes a rule in one paste, and a Postman collection with examples
imports with correct bodies.
